Fair. It's a guess: it compares lines, and the 40% bar is a number I picked. It works for clean renames, but it can guess wrong (two similar boxes) and does it silently.
Making the AI responsible is more exact, because whoever renamed the code knows where the box went. Its weak spot: it only covers the AI's own edits. A rename you make in an editor, or one that arrives with a git pull, would still strand threads. And 'the AI remembers' isn't something to rely on.
What I'd do instead, combining both:
1. Detect for certain: a thread whose box no longer exists is a fact, not a guess.
2. The stop hook hands stranded threads to the AI, like it hands over new comments: 'thread #x is on src/a.rs::Ex, which no longer exists'. The AI moves it with a new `visvet move <thread> <box>`, and it can't finish its turn until none are left. That covers renames from anyone, since the next AI turn catches them.
3. The line matching stays only as a hint in that message ('probably src/a.rs::FileParser, 78% the same'); it no longer moves anything by itself.
So the AI decides, the check is exact, and nothing moves silently. Switch to that?
