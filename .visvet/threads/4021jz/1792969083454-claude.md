**What `extract.rs` does that `file_objects` doesn't:** all the reading of code. It walks tree-sitter's syntax tree and finds types, members, signatures, doc comments, calls, imports and complexity, for one version of one file. That's about 500 lines. `file_objects` never looks at syntax: it calls `extract` twice (old and new), then pairs and diffs what came back.

Agreed on the names. Proposal, named after what each step does:

- `extract.rs` → **`parse.rs`**: read one version of one file
- new **`compare.rs`**: pair old and new versions, diff them, set statuses (`file_objects` and friends)
- `model.rs` → **`connect.rs`**: turn the names each box mentions into arrows (`link`, `Index`)
- `build_review` (read the repo, then run all three) moves to **`review.rs`**, next to the `Review` type it builds

Go with those names?
