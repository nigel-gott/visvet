Fair, the line between them is muddy. How it's meant to split:

1. **`extract.rs`: one version of one file.** Text in, raw objects out: types, members, docs, and the *names* they mention (`Thread`, `git::show`), not yet knowing which box each name means. The only place that knows tree-sitter. No git, no old vs new.
2. **`model.rs`: everything across versions and files.** It
   - reads the files from git and disk (`build_review`),
   - compares old and new versions of each file (`file_objects` plus `pair`, `status`, `diff`), and
   - turns names into arrows across all files (`link`, `Index`, `pick`).

So `model.rs` really does two jobs: **comparing versions** and **linking names**. That's why `file_objects` feels like it belongs elsewhere.

A clearer shape, three stages, one file each:

- `extract.rs`: parse one version (as now)
- **`compare.rs`**: pair a file's old and new versions, diff them, set statuses
- `model.rs`: read the repo, run both, then link names into arrows
