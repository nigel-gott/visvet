Agreed, done properly now: threads follow renames.
- visvet remembers the lines of each thread's box (one number per line, in `.visvet/anchors/`, kept off git).
- When a thread's box disappears, the thread moves to the box at the same level (type to type, member to member, file to file) that shares the most lines with it, if at least 40% match. A rename changes one or two lines, so it matches easily; unrelated code doesn't.
- The move is written into the thread's files, so it's committed and everyone sees it.
- A test covers it: a struct is renamed with its doc comment edited, and the thread follows; then it's replaced by unrelated code, and the thread stays put.
- The 23 threads left behind by earlier renames had nothing remembered yet, so I moved those by hand. None are stranded now; this thread is on `names.rs::FileParser`.
The zoom-to-where-it-was fallback stays for when nothing matches (e.g. a box deleted outright).
