Yes. There are two good options: gix (gitoxide, pure Rust, fast, but a big API that still changes) and git2 (bindings to libgit2, small stable API, but it compiles a C library into the build). Either would replace the process-per-question approach, which runs git once per changed file, and the parsing of git's text output, with typed calls on one open repository. git2 is the shorter change: status with untracked files is one call. gix keeps the build pure Rust. I've written it up as issues/git-library.md. Want me to do it now, and with which library? My pick is git2 for the smaller, steadier code.
