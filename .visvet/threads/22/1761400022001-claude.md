tree-sitter can't see it on its own: it reads each file's syntax, and nothing in `contract.ts` points back at Rust. But the Rust side does say it, on every exported type:

`#[ts(export, export_to = "../ui/src/contract.ts")]`

Options:

1. **ts-rs rule (my pick).** When the extractor sees that attribute, add a **generates** arrow from the Rust type to the same-named type in that file, e.g. `Thread` → `contract.ts::Thread`. Exact, about 15 lines, and it stays right as code changes. Other generators (serde, protobuf…) would each need their own small rule.
2. **Same name in both languages.** Link any Rust and TS types that share a name. No per-library code, but it guesses, and wrong arrows are worse than missing ones.
3. **AI-declared arrows**, e.g. `visvet link <from> <to>`. Works for anything, but they go stale when code moves and nothing checks them.

Go with 1?
