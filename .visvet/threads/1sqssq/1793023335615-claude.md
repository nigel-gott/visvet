**What a cycle is:** A uses B and B uses A, so you can't read either one first. `visvet graph` lists them as problems to fix. Before this fix, most of the cycles it listed weren't real, which hid the real ones.

**False cycle 1, a module and its own files:**
- `src/review.rs` is the module that holds the folder `src/review/`, like a folder holds its files.
- `review.rs::build_review` calls `review/compare.rs::compare_file`. That is an arrow review.rs → compare.rs.
- `compare.rs` starts with `use crate::review::…`, which visvet reads as importing `review.rs`. That is an arrow compare.rs → review.rs.
- So the graph said "cycle: review.rs, compare.rs". But compare.rs just names its own parent module, like a file naming the folder it is in. Nothing needs untangling.
- The same happened for every file in `src/review/`, and for `parse.rs` with `parse/*.rs`.

**False cycle 2, Markdown notes:**
- `ideas/dimensions/README.md` links to `dimensions.md`, and `dimensions.md` links back to its README. Notes link each other on purpose.
- That made all of `ideas/` one "cycle" of 59 files.

**The fix, in this line:**
- Skip arrows that aren't code: Markdown links, generated files and trait implementations (`counts_for_cycles`).
- Skip arrows between a module file and the files in its own folder (`in_submodule`).
- The arrows stay on the map; only the cycle list changes.

**Result:** the list went from 3 cycles (one of 59 files) to 1 real one, among the `src/review/parse/` sibling files.
