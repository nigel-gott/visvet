Good instinct, there are two real relationships here:
1. **Cargo.toml → Cargo.lock: 'generates'.** Cargo writes the lock file from the manifest, the same as ts-rs writing contract.ts, and we already have that arrow kind. A file-level detector with known pairs is enough: Cargo.toml → Cargo.lock, package.json → package-lock.json, and the same for other package managers.
2. **Cargo.toml → src/main.rs: 'builds'.** The manifest names the crate, and Cargo builds it starting from `src/main.rs` (or `src/lib.rs`, or the `[[bin]]` path). That arrow says 'this is where the program starts'. The UI's `package.json` → `index.html` / `main.tsx` is the same idea. It would be a new arrow kind.
Cargo.lock → src: I'd skip it. The lock only pins versions, and the code never refers to it.
The dependencies Cargo.toml lists are the third link, but they belong with the 'library boxes' idea (code → library box ← Cargo.toml), not as an arrow to src.
