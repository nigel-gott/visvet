Yes, it smells. `front` is the **front matter** of a Markdown file: the `key: value` lines at its top, like `kind: issue` and `status: open`. The UI uses it to label the box. What's wrong with it:

- **Every** `CodeUnit` carries it, Rust structs and TS functions included, almost always empty. Only Markdown files fill it.
- `front` is jargon, and a map of strings says nothing about what it holds.
- `kind` in it competes with the unit's real `kind`.

Two cleaner shapes:

1. **Typed labels (my pick).** Replace it with `labels: Option<Labels>`, `None` for code, where `Labels { kind: Option<LabelKind>, status: Option<WorkStatus> }`. `LabelKind` is issue, milestone or a custom word, and `WorkStatus` is open, done… Other front-matter keys are ignored. Clear, but only the keys we know about show.
2. **Generic, but honest.** Keep any key, as `tags: Vec<Tag>` with `Tag { key: TagKey, value: String }` micro types, documented as "Markdown front matter shown on the box". Every key shows, but it stays stringly.

You asked for generic earlier, but I'd go with 1: the map only needs kind and status today, and new keys can be added as fields when needed. Which do you want?
