Got it, not now. Some ideas for issues on the map:

1. **An issue is a thread that waits.** Same files in `.visvet/threads/`, but kind `issue`: it sits on a box until someone fixes it, without blocking me the way a comment does. So it's a git-first tracker that lives next to the code.
2. **Issues on the map.** A 🐞 badge with a count on each box, adding up through folders like debuffs do, plus an "issues" lens that tints boxes by how many open issues they hold, so you see where the problems cluster.
3. **Make one from a debuff.** Click 🌀 42 on `mapView`, then "make issue": it carries the numbers, and it can **close itself** once the debuff is gone, since visvet can check that from the code.
4. **Issues across several boxes.** e.g. "Debuffs.tsx ↔ Views.tsx cycle" outlines both boxes and the arrows between them, so you see its blast radius.
5. **"Is this done?" from the diff.** When a change touches an issue's box, the issue asks to be checked, and I can answer with what changed.
6. **Mirror to GitHub or Forgejo issues** later, with a link back to the box, for people who don't use visvet.

I'd start with 1, 2 and 3. Which of these appeal to you?
