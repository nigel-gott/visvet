Fair to doubt it, but it's true: Rust's standard library has no purely textual way to resolve '..'.
- `Path::join("../x")` just appends; the '..' stays in the path.
- `std::fs::canonicalize` does resolve it, but only for a file that exists on disk right now (and it follows symlinks and returns an absolute path). Ours often don't exist: a link in the old version of a file at the base commit, or a link to a missing file.
- `std::path::absolute` (new in Rust 1.79) makes a path absolute, and its docs say it deliberately does NOT resolve '..' on Unix, because with symlinks 'a/b/..' may not be 'a'.
- `Path::components()` splits out the '..' parts, but folding them away is left to you, which is what our 9 lines do.
That's why crates like `path-clean` exist: it does exactly this. Options: keep our 9 lines, or swap in `path-clean` (one small dependency, one line here). Which do you prefer?
