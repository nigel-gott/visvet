A git library wouldn't help here. The '..' never comes from git: git's own paths are always clean and repo-relative (`src/review/parse.rs`). It comes from text inside our source files, like `import x from '../model'` or a Markdown link `(../src/review.rs)`. Turning that written text into a repo path is the job of each language's import rules, not of git, so a git library (gix or git2) has nothing for it either.
Separately, visvet does call the `git` command-line tool today (`src/git.rs`) to list files and read old versions. Swapping that for a git library (gix) is a reasonable change on its own (faster, no shelling out), but it wouldn't remove `join`.
So: keep `join` (or `path-clean`)? And should I write the gix swap up as an idea for after the review?
