You're right that it's per-language logic, but tree-sitter stops before it. Tree-sitter only parses: it tells us 'this is an import, and its text is ../model'. Working out which file that means is the language's resolution rules (TypeScript tries model.ts, model.tsx, model/index.ts and tsconfig paths; Rust has its mod rules), and tree-sitter leaves that out on purpose.
Tools that do resolve:
- Language servers (rust-analyzer, tsserver): exact, because they run the real rules, but heavy and one per language.
- GitHub's stack-graphs, built on tree-sitter for code navigation: resolves names per language, but it's a big system, and as far as I know GitHub no longer actively develops it.
So each parser file does its own language's part (`parse/ts.rs` tries .ts, .tsx and index.ts; `parse/rust.rs` tries x.rs and x/mod.rs), and `join` is only the shared last step: folder + relative text → repo path. A language server would be the more exact path later (it fits the 'languages from tag queries' idea), but it's a big change for 9 lines.
So: keep `join` as it is for now?
